# 👥 Руководство для контрибьюторов / Contributing Guide

Спасибо за интерес к развитию проекта **SurvivalCalc**!  
Мы рады вкладу каждого: исправлениям багов, оптимизации алгоритмов, расширению базы продуктов/снаряжения, улучшению UI и переводу.

---

## 🧭 Ключевые принципы проекта (Architecture Philosophy)

Перед тем как писать код, пожалуйста, ознакомьтесь с фундаментальными принципами проекта:
1. **100% Offline-First:** приложение должно полностью работать в авиарежиме в горах и тайге без доступа к интернету. Никаких обязательных внешних API или серверных зависимостей.
2. **Zero Telemetry & Privacy:** никаких трекеров, аналитики и передачи персональных данных.
3. **Clean Architecture / Feature-First:** код разбит по фичам (`lib/features/*`) с четким разделением на слои `domain`, `data`, `presentation`.
4. **State Management:** используется `flutter_riverpod` (2.6+). Логика расчетов выносится в чистые доменные сервисы без привязки к виджетам.
5. **Outdoor UI Theme:** высококонтрастная тема (Material 3 Dark, OutdoorTheme), читаемость на ярком солнце, крупные элементы управления.

## 🛠️ Быстрый старт и окружение (Development Setup)

### Требования:
- **Flutter SDK:** stable (версия 3.24+ / 3.44+)
- **Dart SDK:** 3.5+ (Null Safety)
- Рекомендуемые IDE: Android Studio, VS Code или Antigravity IDE

### 1. Клонирование и зависимости:
```bash
git clone https://github.com/kobaltgit/SurvivalCalc.git
cd SurvivalCalc
flutter pub get
```

### 2. Запуск в режиме разработки:
* **Веб-версия:**
  ```bash
  flutter run -d chrome
  ```
* **Android-устройство или эмулятор:**
  ```bash
  flutter run -d android
  ```

## 🧪 Тестирование и проверка качества (Quality Assurance)

Перед отправкой изменений обязательно выполните локальную валидацию:

### 1. Статический анализ:
В кодовой базе поддерживается правило **0 предупреждений линтера**:
```bash
dart analyze
```

### 2. Запуск unit- и widget-тестов:
Все тесты должны успешно проходить:
```bash
flutter test
```

Если вы добавляете новую математическую логику, формулы или алгоритмы — обязательно покройте их новыми unit-тестами в папке `test/`.

## 🥫 Добавление продуктов и снаряжения в базу (Datasets)

- **База продуктов (57+ позиций):** хранится в `assets/data/food_db.json`. При добавлении нового продукта убедитесь, что указаны все нутриенты на 100 г (калории, БЖУ, ключевые микроэлементы) и эталонный вес порции.
- **База снаряжения (66+ позиций):** хранится в `assets/data/gear_db.json`. Указывайте реальный вес в граммах, категорию и признак сезонности (`all`, `summer`, `winter`).

## 🔀 Процесс внесения изменений (Workflow & Pull Requests)

1. **Создайте ветку:**
   Ответвляйтесь от актуальной ветки разработки:
   ```bash
   git checkout -b feat/my-new-feature
   # или
   git checkout -b fix/issue-description
   ```
2. **Формат коммитов (Conventional Commits):**
   Придерживайтесь структурированных сообщений:
   - `feat: добавить фильтр продуктов по безлактозной диете`
   - `fix: исправить расчет расхода газа в зимнем режиме`
   - `docs: обновить руководство пользователя в вики`
   - `test: добавить тесты на парсер путевых точек GPX`
3. **Отправьте Pull Request:**
   Опишите суть изменений, приложите скриншоты (если менялся UI) и убедитесь, что тесты в CI проходят успешно.
