# 🛡️ Политика безопасности / Security Policy

## 1. Поддерживаемые версии / Supported Versions

Мы поддерживаем актуальные стабильные версии приложения **SurvivalCalc** и оперативно устраняем обнаруженные проблемы безопасности.

| Версия / Version | Поддержка / Supported | Примечания / Notes |
| :--- | :---: | :--- |
| **v1.1.x** | ✅ | Текущая стабильная ветка разработки |
| **v1.0.x** | ✅ | Релизная стабильная версия |
| `< 1.0.0` | ❌ | Устаревшие прототипы и тестовые сборки |

## 2. Сообщение об уязвимости / Reporting a Vulnerability

Если вы обнаружили потенциальную уязвимость или проблему безопасности в **SurvivalCalc**:

1. **Не создавайте публичный Issue** в репозитории GitHub.
2. Воспользуйтесь официальным приватным механизмом:
   - Перейдите во вкладку **Security** репозитория ➔ **Report a vulnerability** ([GitHub Private Vulnerability Reporting](https://github.com/kobaltgit/SurvivalCalc/security/advisories/new)).
3. Альтернативно вы можете связаться напрямую с мейнтейнером:
   - Через официальный Telegram-канал/чат: [t.me/survivalcalc](https://t.me/survivalcalc)
   - Через личные сообщения в профиле GitHub: [@kobaltgit](https://github.com/kobaltgit)

### Что указать в отчете:
- Описание уязвимости и потенциальный вектор атаки.
- Шаги для воспроизведения проблемы (PoC, тестовый GPX-файл или QR-строка).
- Затронутые платформы (Android APK, Web/Браузер).

### Сроки реагирования:
- Первичное подтверждение получения отчета: **в течение 48 часов**.
- Анализ и выпуск исправления: **в течение 7–14 дней** в зависимости от критичности.

## 3. Архитектура безопасности SurvivalCalc / Security Architecture

Проект **SurvivalCalc** спроектирован по принципу **Privacy & Security by Design**:

### 3.1. 100% Offline-First (Полная автономность)
- Приложение не использует внешние бэкенд-серверы, облачные базы данных, cookie-сессии или удалённую аутентификацию.
- Вся бизнес-логика (расчет BMR/TDEE, генерация раскладок, развесовка снаряжения) выполняется локально в песочнице устройства.
- Риск утечки данных с удалённого сервера физически исключён из-за отсутствия самого сервера.

### 3.2. Безопасность парсинга внешних данных (Data Parsing & Ingestion)
- **GPX 1.1 XML:** импорт треков защищен от атак типа XXE (XML External Entity), бомб распаковки и переполнения памяти при обработке слишком длинных полилиний.
- **QR-Синхронизация:** передаваемые Base64/Gzip снапшоты профилей строго валидируются по схеме данных перед десериализацией и защищены от инъекций вредоносного содержимого.

### 3.3. Локальные данные и разрешения (Permissions & Local Storage)
- Доступ к GPS-геолокации запрашивается исключительно во время записи трека на экране «В пути» и не передается третьим сторонам.
- Доступ к камере запрашивается только для съемки фото-меток или встроенного сканирования QR-кодов.
- Все сохраненные походы, шаблоны и кэш карт хранятся во внутреннем изолированном хранилище приложения (`SharedPreferences` / Sandbox Storage).
